Common errors & fixes

Read the message carefully. Try the safe diagnostic step before changing settings.

“command not found” / “not recognized as an internal command”

The tool may not be installed, or its folder is not in PATH. Check the installation guide, reopen the terminal and verify with where toolname on Windows or which toolname on Linux/macOS. Do not download random executable files.

“Permission denied” / “Access is denied”

You may not have permission for that file or action. Check the file owner and permissions. Use administrator/root privileges only when you understand why they are needed; do not run every command as administrator.

“Connection timed out”

The destination may be offline, a firewall may block the connection, DNS may be failing, or the route may be unavailable. Check your own internet connection, hostname and service status. Only test systems you are authorised to troubleshoot.

“Name or service not known” / DNS lookup failed

Check spelling, DNS configuration and internet connectivity. On your own machine you can compare a hostname lookup with a known public domain; avoid changing network settings unless you know how to restore them.

Python: “ModuleNotFoundError”

Install the missing package in the same Python environment that runs your script. Check python --version and python -m pip show package_name. Prefer a virtual environment for each project.

Linux: “No such file or directory”

Check the current folder with pwd, list files with ls -la, and verify spelling/capitalisation. Linux paths are case-sensitive.

Browser says “Your connection is not private”

Do not bypass the warning on a site you do not control. Check the URL, device date/time and certificate status. If it is your site, renew/configure its TLS certificate and server chain.

Tool shows no results or unexpected output

Confirm the target is in scope, the correct interface/host is selected, the tool version is supported and the input is valid. Reproduce the issue in a lab and save the exact error text.

Rules every ethical hacker follows

Permission is not optional. A learning goal never overrides another person's privacy or safety.

📜

Get written permission

Define the exact domain, IP, accounts, test window and allowed techniques before testing.

🔒

Protect data

Never access, copy, publish or modify private data. Stop if sensitive information appears.

🤝

Report responsibly

Document impact safely, notify the owner through an approved channel and allow time to fix.

Out of scope: attacking public websites, accounts, Wi-Fi networks or devices without explicit authorisation; credential theft; malware; persistence; evasion; denial-of-service; or accessing someone else's data. Use CTFs and isolated labs instead.

Frequently asked questions

Quick answers for first-time learners.

Do I need to know coding before learning ethical hacking?

No. Start with computer and networking basics. Learn Python and a little HTML/JavaScript as you progress; coding makes security concepts easier to understand.

Can I learn using only Windows?

Yes. Begin with Windows Terminal, PowerShell and browser DevTools. Later, use a Linux virtual machine for Linux practice.

Is Kali Linux required?

No. Kali is a tool-rich Linux distribution, not a prerequisite. Learn networking, Linux and security fundamentals first.

Can I practise on a real website?

Only if you own it or have explicit written permission that clearly covers the test. Otherwise use a local lab or authorised CTF platform.

Will this site make me job-ready?

This is a learning starting point, not a certification or job guarantee. Build projects, practise in legal labs, document your work and study recognised security fundamentals.
